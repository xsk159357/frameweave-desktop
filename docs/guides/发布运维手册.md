### 1.2 选型建议（按你的情况）
- **无企业资质（个人开发者）**：GoGetSSL Code Signing SSL（$290.70，官方注明个人可申请）——不推荐硬走 OV 企业渠道。
- **有企业资质**：国内阿里云/腾讯云 OV（人民币、发票、中文客服）或 GoGetSSL（便宜）。
- **不需要频繁签名/多人协作**：普通 OV + USB Token 即可；需要 CI 自动签名选云签名（Cloud Code Signing / Azure Trusted Signing）。

### 1.3 申请流程（OV 通用）
1. 下单 → CA 发验证邮件 → 提交主体资料：
   - Business：营业执照/主体证明 + 申请人邮箱域名验证（如 admin@你的域名）
   - Individual（GoGetSSL/Sectigo）：个人身份 + 邮箱验证
2. CA 签发 → 证书通常装在 **USB Token**（如 Safenet eToken / Feitian）或云托管。
3. 从 Token 导出/使用签名密钥（见 1.4）。

### 1.4 electron-builder 接入两种方式
**A. 有 pfx/p12 文件**（申请时可要求导出，或从 Token 导出含私钥 pfx）：
```powershell
# publish.ps1 已支持：用环境变量覆盖
$env:FRAMEWEAVE_PFX = "C:\certs\frameweave-ov.pfx"
$env:FRAMEWEAVE_PFX_PASSWORD = "****"
$env:FRAMEWEAVE_SIGNTOOL = "C:\Program Files (x86)\Windows Kits\10\bin\10.0.26100.0\x64\signtool.exe"
pwsh scripts/publish.ps1
```
**B. 证书在 USB Token / 系统证书库**（无 pfx）：electron-builder 原生支持
```powershell
$env:CSC_LINK = "C:\certs\my-cert.pfx"      # 或 token 的 pfx 导出
$env:CSC_KEY_PASSWORD = "****"
cd desktop; npx electron-builder --win nsis   # electron-builder 自动签名
```
Token 场景若导出不便：用 signtool 引用令牌证书 `signtool sign /sha1 <thumbprint> /tr http://timestamp.digicert.com /td SHA256 ...`（publish.ps1 的签名段可改）。

### 1.5 签名后必须做
- **重建 blockmap + latest.yml 的 sha512**：签名改变文件字节，publish.ps1 已内置此步骤（M8 修复）。
- **时间戳**：publish.ps1 已用 `/tr http://timestamp.digicert.com /td SHA256`（DigiCert 免费时间戳，离线也可验证签名时间）。

## 二、真实更新源部署（electron-updater generic）

### 2.1 托管选择（按国内访问与成本排序）
| 方案 | 成本 | HTTPS | 说明 |
|---|---|---|---|
| 阿里云 OSS + CDN | 低（流量付费） | 免费证书 | 国内首选，配 CDN 加速 |
| 腾讯云 COS + CDN | 低 | 免费证书 | 同上 |
| GitHub Releases | 免费 | 有 | 国内慢/不稳，electron-updater 有 github provider（改 publish 配置） |
| Cloudflare Pages / 自建 nginx | 免费/低 | 有 | 需自有域名 |

### 2.2 部署结构（关键：latest.yml 必须与 exe 同目录）
```
你的站点根:
└── frameweave/
    ├── latest.yml                     # electron-updater 读取的版本清单
    ├── FrameWeave-Setup-0.2.9.exe     # 当前版本安装包（electron-updater 按 latest.yml path 下载）
    └── FrameWeave-Setup-0.2.9.exe.blockmap
```
（旧版本可放子目录 `release/<ver>/` 保留，latest.yml 的 path 指向当前 exe 即可。）

### 2.3 打包+组装（本机执行）
```powershell
cd F:\1223\解说工坊\FrameWeave
pwsh scripts/publish.ps1        # 打包 + 签名 + 组装 release/0.2.9/（含三件套）
pwsh scripts/check_release.ps1  # 校验 latest.yml sha512 == 实际 exe 哈希
```

### 2.4 上传
- **阿里云 OSS**：控制台建 Bucket（公共读）→ 绑 CDN + HTTPS 域名 → 把 `release/0.2.9/` 下三个文件上传到 `frameweave/` 前缀。
- **GitHub Releases**：创建 Release v0.2.9 → 上传三件套 → 配置见 2.5。

### 2.5 配置客户端指向真实源（二选一）
**A. 改 package.json（随包分发，推荐）**：
```json
"publish": [{ "provider": "generic", "url": "https://你的域名/frameweave" }]
```
**B. 不改代码，运行时覆盖（联调/企业部署）**：main.cjs 已支持
```powershell
$env:FRAMEWEAVE_UPDATE_URL = "https://你的域名/frameweave"
```

### 2.6 客户端验证（M15 已验证的链路）
1. 本机先装旧版（如 0.2.8）→ 启动 → 5s 后 autoUpdater.checkForUpdates()
2. 日志/黑匣子 debug.log 应出现 `Checking for update` → `Found version 0.2.9`
3. 弹「发现新版本」→ 下载 → sha512 校验 → 「更新就绪」→ 重启安装 → 版本变为 0.2.9
4. 升级后 WS 事件回归（execution_done 到达）确认无回归

### 2.7 上线注意
- 每次发版必须 **bump desktop/package.json version**（latest.yml 的 version 大于客户端当前才提示）。
- 上传后先自己用 `curl https://你的域名/frameweave/latest.yml` 确认 200 + 版本号正确。
- 证书签名（第一节）与更新源是两件事：更新源不要求签名证书，但安装包签名后 SmartScreen 才友好。

## 三、GitHub Releases 方案（已选定，2026-10）

### 3.1 前置（一次性，需用户提供）
1. GitHub 账号 + 建仓库（如 `frameweave-desktop`，private 亦可——Releases 资产公开下载；仓库本身 private 时 Release 仍可公开）。
2. 生成上传令牌：GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → 勾选仓库的 **Contents: Read & write** 权限 → 复制 token（即 GH_TOKEN）。

### 3.2 发布命令（每次发版）
\`\`\`powershell
cd F:\1223\解说工坊\FrameWeave
$env:GITHUB_OWNER = "<你的GitHub用户名>"
$env:GITHUB_REPO  = "<仓库名>"
$env:GH_TOKEN     = "<ghp_xxx>"
pwsh scripts/publish.ps1           # 1) 打包+签名+组装 release/<ver>/ 三件套
pwsh scripts/publish-github.ps1    # 2) 上传 exe+blockmap+latest.yml 到 GitHub Release（draft）
\`\`\`
3. 到 `https://github.com/<owner>/<repo>/releases` 点 **Publish release**（新标签默认 draft），用户端即可收到更新。

### 3.3 客户端指向 GitHub
desktop/package.json 的 publish 改为：
\`\`\`json
"publish": [{ "provider": "github", "owner": "<GitHub用户名>", "repo": "<仓库名>" }]
\`\`\`
electron-updater 会按 `https://github.com/<owner>/<repo>/releases/download/v<版本>/<文件名>` 下载；
**发版铁律**：tag 必须是 `v<desktop.version>`（electron-builder/publish-github.ps1 均按此命名）。

### 3.4 国内下载慢的缓解（可选）
- 直连 GitHub Releases 走 codeload，国内一般；人多了可后续给大安装包换国内 OSS 分流（届时把 publish 改回 generic 指向 OSS）。
- 不推荐依赖 ghproxy 等第三方镜像（不稳定且有合规风险）。

## 六、一键发布（scripts/release-to-github.ps1）
```powershell
cd F:\1223\解说工坊\FrameWeave
pwsh scripts/release-to-github.ps1                  # 出包 + 上传 + 正式发布（一步到位）
pwsh scripts/release-to-github.ps1 -SignOff         # 无证书阶段：出包跳过签名
```
