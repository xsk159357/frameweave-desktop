# FrameWeave 云端授权与发布规范

> 文档用途：统一记录授权服务器、客户端认证、密钥边界、打包发布和验收规则。
> 版本基线：v0.2.10
> 更新时间：2026-10-05

## 1. 服务器定位

**韩国授权服务器（shouquan.frameweave.top → 43.108.23.200）**承载 FrameWeave 云端授权、客户端更新源与官方插件分发三通道，不用于文档存储。服务器职责：账号、QQ 邮箱验证码、登录、密码重置、设备绑定、订阅校验、卡密激活与管理签发。

> 历史沿革：2026-10-13 前授权服务部署于旧服「雨云日本中转 154.36.178.119（frameweave.ameaaos.com）」，2026-10-14 起全部迁移至韩国授权服务器（见「服务器自动更新说明.md」§5 迁移记录）；旧域名 ameaaos.com 返回 502 已废弃，不得复用。

服务器地址、root 密码、AccessKey Secret 和其他凭据严禁写入本文件、源码、日志、安装包、GitHub 或聊天记录。曾经暴露的凭据必须轮换。

## 2. 目标架构

客户端通过 HTTPS 访问 `https://shouquan.frameweave.top`（韩国授权服务器，Cloudflare/OpenResty HTTPS 反代 `127.0.0.1:8789` 云端授权服务）。DirectMail 凭据只存在服务器。正式客户端不携带阿里云 AccessKey，不在客户端签发或验证卡密，不以本地文件作为正式账号数据源。

三条通道（均落在韩国授权服务器同一台）：
- **授权**：`https://shouquan.frameweave.top/api/...` → OpenResty 反代 127.0.0.1:8789（health 实测 `service=frameweave-cloud, protocol_version=3`）
- **更新**：`https://shouquan.frameweave.top/update/`（latest.yml + exe + blockmap，客户端 `FRAMEWEAVE_UPDATE_URL` 显式设置时禁用镜像回退）
- **插件**：`https://shouquan.frameweave.top/plugins/*.zip`（40+ 官方插件包 + ed25519 .sig，商城 `download_url` 直指此处）

## 3. 云端认证接口

- `POST /api/auth/email/send-code`
- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/password/reset`
- `POST /api/auth/verify`
- `POST /api/auth/activate`
- `GET /api/health`

注册需要 QQ 邮箱验证码、密码和确认密码；注册不需要卡密。卡密在登录后的账户能力中独立激活。

## 4. DirectMail 密钥边界

AccessKey、发信地址和服务配置只放在服务器环境变量或服务器端 `.env`，不进入前端、Electron、安装包、GitHub Release、Git 历史、日志和错误回显。项目根 `.gitignore` 必须忽略 `.env`、`*.env` 和 `backend/.env`。

## 5. 验证码规则

- 仅接受规范化后的 `@qq.com` 地址
- 验证码 6 位数字，5 分钟有效
- 成功验证立即失效，错误 5 次后失效
- 同邮箱 60 秒冷却，每日最多 10 次
- 发送和校验必须有并发保护
- 找回密码不得直接暴露账号是否存在
- 正式部署应增加 IP、设备和全局限流，并记录发送审计

## 6. 客户端与本地后端边界

客户端本地后端负责工作流、媒体处理、节点运行和本地素材。正式账号、订阅和卡密状态以云端为准。协议握手字段为：`service=frameweave`、`version=0.2.10`、`protocol_version=3`、`auth_revision=email-code-v2`。Electron 只有在字段兼容时才复用 8788 端口；启动前清理旧后端进程树。

## 7. 打包强制流程

`build-installer.ps1` 必须先调用 `build-backend.ps1`，禁止复用旧 backend-dist。顺序：PyInstaller 重建后端、校验 EXE、校验认证路由、构建前端、构建 Electron、生成 NSIS、生成 latest.yml/blockmap、VM 验收、上传 GitHub Release。

## 8. 发布规则

认证/API/协议改动必须升级版本号。0.2.10 是当前全量加固版本。GitHub Release 必须包含安装包、blockmap、latest.yml，并验证下载 URL、大小、SHA512 和 VM 安装结果。首次分发和 OV 代码签名按既定决策暂不处理。

## 9. 当前验收基线

已验证：阿里云 DirectMail 真实发送、后端语法、TypeScript、Vite、PyInstaller、NSIS、OpenAPI 认证路由、健康接口、build-info 和 v0.2.10 GitHub 发布。

长期升级：部署云端授权、迁移云端数据库、Argon2id/scrypt 密码迁移、Redis/数据库验证码存储、HTTPS/Nginx/systemd 正式部署。
## 10. 授权后台管理网站（v0.2.11）

后台入口：`https://shouquan.frameweave.top/admin/`（OpenResty HTTPS 反代 127.0.0.1:8789；旧入口 `frameweave.ameaaos.com/admin/` 已随旧服废弃）

功能：
- 管理密钥登录（环境变量 `FRAMEWEAVE_ADMIN_KEY`，会话 token 8 小时）
- 签发卡密（月卡/季卡/年卡，单次最多 50 张）
- 用户管理（列表、禁用/启用 status）
- 邮件发送审计（mail_audit 表，最近 300 条）

管理密钥只存放在服务器 `/opt/frameweave-cloud/cloud.env`，严禁写入本项目仓库、GitHub、日志或聊天记录。2026-10-05 已完成一次密钥轮换（旧值废弃，新值仅存在于服务器环境文件）。

## 13. E9 密码哈希升级 与 E10 验证码持久化（2026-10-06）

- E9：新密码哈希改为 `scrypt$N$R$P$<hex>`（N=16384, R=8, P=1, dklen=32，Python 标准库 hashlib.scrypt，无第三方依赖）。旧 SHA256 哈希登录验证通过后自动升级为 scrypt（渐进迁移，无需用户改密）。独立实例验收：scrypt 注册/错误密码拒绝/正确登录/旧哈希登录后自动升级，全部 PASS。
- E10：验证码从内存字典迁到 SQLite。`email_codes` 表存未消费验证码（含 expires_at/attempts），新增 `send_log` 表记录每日发送历史（替代内存 _SENDS 的每日 10 次限制）。服务重启后未过期验证码仍有效。独立实例验收：发码→重启→重置成功，PASS。
- 生产已部署（0.2.11）：send_log 表已建，现存 test@fw.local 为旧哈希将在下次登录迁移。

## 14. t3 服务器/部署安全加固（2026-10-17，随后端发布生效）

> 本节约定服务器发布前的**必改环境变量**与**必需的反代配置**；未按本节约定的部署不视为安全基线。

### 14.1 服务器必需环境变量（`/opt/frameweave-cloud/cloud.env`）

| 变量 | 必填 | 说明 |
|---|---|---|
| `FRAMEWEAVE_ADMIN_KEY` | 是 | 管理后台登录密钥（≥8 位）。**未配置时 `/api/admin/login` 拒绝一切登录（含空串）**，且启动时告警 |
| `FRAMEWEAVE_CARD_SECRET` | 是 | 卡密 HMAC 密钥。**未配置时使用空密钥，卡密可被任何人伪造**，启动时告警 |
| `FRAMEWEAVE_ADMIN_ALLOW_IPS` | 建议 | 管理后台 IP 白名单（逗号分隔）。配合 `FRAMEWEAVE_TRUST_XFF=1` 在反代后真实生效 |
| `FRAMEWEAVE_VERIFY_SECRET` | 建议阅读 | auth 响应 HMAC 签名密钥。**注意：** 签名密钥默认值同时内嵌于客户端（obf 混淆），属纵深防御层而非强防伪控制；缺省不告警、不阻断（保证现网客户端兼容），真正的授权判定以服务端为准 |
| `FRAMEWEAVE_TRUST_XFF` | 反代部署建议 | 设为 `1` 才接受 `X-Forwarded-For`（仅信任回环对端）。默认 `0` 保持旧行为（反代下所有 IP 记为 127.0.0.1） |

### 14.2 OpenResty 反代必需配置（启用 TRUST_XFF 时）

```nginx
location /api/ { proxy_pass http://127.0.0.1:8789; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; }
location = /admin { proxy_pass http://127.0.0.1:8789; }
```
- 服务必须仅监听 127.0.0.1（`--bind 127.0.0.1`，默认），禁止 `0.0.0.0` 暴露。
- 启用 TRUST_XFF 后，IP 限流（验证码/登录/管理登录）与 `FRAMEWEAVE_ADMIN_ALLOW_IPS` 才按真实客户端 IP 生效；未启用则退化为全局计数（可用性风险）。

### 14.3 新增的服务器行为（契约不变）

- 请求体上限 1MB：超限返回 `413 {"ok":false,"code":"body_too_large"}`（防内存耗尽 DoS）。
- 后台页面/接口响应头：`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、CSP（`frame-ancestors 'none'` 等）、`Cache-Control: no-store`。
- 日志脱敏：云服务 dev 邮件模式只打印验证码后两位（需要完整码做本地 E2E 时设 `FRAMEWEAVE_DEV_MAIL_VERBOSE=1`）；任何日志不落明文凭据/验证码。
- `admin/ops`：`ops_base` 仅允许 `http(s)://127.0.0.1|localhost`（阻断 file:// 与外部 SSRF），错误信息不再透出异常类型/内部路径。
- 备份/恢复：备份现**包含** `password_hash/salt/cards_used`（否则恢复后全部账号无法登录）；**不包含**会话 token，恢复后统一重置 token（用户需重新登录）；恢复内置事务（失败整体回滚）并自动生成 `backups/pre_restore_*.db` 快照（保留最近 10 份）。

### 14.4 服务器发布步骤（每次更新授权服务）

1. 本地 `python -m py_compile backend/cloud_server.py`；同步校验 `backend/admin.html` 渲染（XSS 已由 t2 重设计消除，编辑按钮仅传条目 id + `esc(qs())` 双保险）。
2. `pwsh scripts/update-cloud-auth.ps1`（脚本已内置：远端 sha256 完整性校验 + `py_compile` + 服务重启 + `/api/health` + 非 QQ 邮箱拒绝自检；python runner 自动回退 venv）。
3. 确认 `cloud.env` 含 §14.1 全部必填变量；OpenResty 按 §14.2 配置并 reload。
4. 上线后回环验证：`/api/health` protocol_version=3；`/api/admin/login` 空密钥必须被拒；后台页面响应头含 `X-Frame-Options: DENY`。
