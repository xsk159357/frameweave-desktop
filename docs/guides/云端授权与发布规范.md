# FrameWeave 云端授权与发布规范

> 文档用途：统一记录授权服务器、客户端认证、密钥边界、打包发布和验收规则。
> 版本基线：v0.2.10
> 更新时间：2026-10-05

## 1. 服务器定位

“雨云日本中转”服务器用于 FrameWeave 云端授权，不用于文档存储。服务器职责：账号、QQ 邮箱验证码、登录、密码重置、设备绑定、订阅校验、卡密激活与管理签发。

服务器地址、root 密码、AccessKey Secret 和其他凭据严禁写入本文件、源码、日志、安装包、GitHub 或聊天记录。曾经暴露的凭据必须轮换。

## 2. 目标架构

客户端通过 HTTPS 访问 `frameweave.ameaaos.com`，Nginx 反代至 `127.0.0.1:8789` 云端授权服务。DirectMail 凭据只存在服务器。正式客户端不携带阿里云 AccessKey，不在客户端签发或验证卡密，不以本地文件作为正式账号数据源。

## 3. 云端认证接口

- `POST /api/auth/email/send-code`
- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/password/reset`
- `POST /api/auth/verify`
- `POST /api/auth/activate`
- `GET /api/health`

注册需要 QQ 邮箱验证码、密码和确认密码；注册不需要卡密。卡密在登录后的账户能力中独立激活。

## 4. DirectMail 密钥边界

AccessKey、发信地址和服务配置只放在服务器环境变量或服务器端 `.env`，不进入前端、Electron、安装包、GitHub Release、Git 历史、日志和错误回显。项目根 `.gitignore` 必须忽略 `.env`、`*.env` 和 `backend/.env`。

## 5. 验证码规则

- 仅接受规范化后的 `@qq.com` 地址
- 验证码 6 位数字，5 分钟有效
- 成功验证立即失效，错误 5 次后失效
- 同邮箱 60 秒冷却，每日最多 10 次
- 发送和校验必须有并发保护
- 找回密码不得直接暴露账号是否存在
- 正式部署应增加 IP、设备和全局限流，并记录发送审计

## 6. 客户端与本地后端边界

客户端本地后端负责工作流、媒体处理、节点运行和本地素材。正式账号、订阅和卡密状态以云端为准。协议握手字段为：`service=frameweave`、`version=0.2.10`、`protocol_version=3`、`auth_revision=email-code-v2`。Electron 只有在字段兼容时才复用 8788 端口；启动前清理旧后端进程树。

## 7. 打包强制流程

`build-installer.ps1` 必须先调用 `build-backend.ps1`，禁止复用旧 backend-dist。顺序：PyInstaller 重建后端、校验 EXE、校验认证路由、构建前端、构建 Electron、生成 NSIS、生成 latest.yml/blockmap、VM 验收、上传 GitHub Release。

## 8. 发布规则

认证/API/协议改动必须升级版本号。0.2.10 是当前全量加固版本。GitHub Release 必须包含安装包、blockmap、latest.yml，并验证下载 URL、大小、SHA512 和 VM 安装结果。首次分发和 OV 代码签名按既定决策暂不处理。

## 9. 当前验收基线

已验证：阿里云 DirectMail 真实发送、后端语法、TypeScript、Vite、PyInstaller、NSIS、OpenAPI 认证路由、健康接口、build-info 和 v0.2.10 GitHub 发布。

长期升级：部署云端授权、迁移云端数据库、Argon2id/scrypt 密码迁移、Redis/数据库验证码存储、HTTPS/Nginx/systemd 正式部署。
## 10. 授权后台管理网站（v0.2.11）

后台入口：`https://frameweave.ameaaos.com/admin/`（OpenResty HTTPS 反代 127.0.0.1:8789）

功能：
- 管理密钥登录（环境变量 `FRAMEWEAVE_ADMIN_KEY`，会话 token 8 小时）
- 签发卡密（月卡/季卡/年卡，单次最多 50 张）
- 用户管理（列表、禁用/启用 status）
- 邮件发送审计（mail_audit 表，最近 300 条）

管理密钥只存放在服务器 `/opt/frameweave-cloud/cloud.env`，严禁写入本项目仓库、GitHub、日志或聊天记录。2026-10-05 已完成一次密钥轮换（旧值废弃，新值仅存在于服务器环境文件）。

## 11. E6 云端加固内容（v0.2.11）

限流：
- 验证码：每邮箱 60s 冷却 + 每日 10 次、每 IP 每小时 20 次、每设备每小时 10 次、全局每分钟 30 次
- 登录：每 IP 5 分钟 20 次、每账号连续失败 5 次锁定 10 分钟

新增表：`mail_audit`（发送审计）、`rate_limits`（窗口限流）、`admin_tokens`（管理会话）、sessions 增加 `status` 字段（禁用/启用）。

部署变更：服务器新增项目专用 venv `/opt/frameweave-cloud/venv` 并安装 `alibabacloud_dm20151123`（1.11.1），systemd 已切换为 venv 运行（原先系统 python 无该 SDK 导致真实发信失败）。
## 12. E7 完整验收与 E8 客户端同步（2026-10-06，v0.2.11）

- E7 回环：服务器上以独立端口/临时库运行同一份 `cloud_server.py`，dev 邮件模式全自动跑通 19 项断言（注册/登录错误拦截/验证/reset/换密登录/后台签卡/激活/禁用后登录拦截/审计计数），全部通过；生产真实发信已在 v0.2.11 上线时单独验证（DirectMail SDK 装于 `venv`）。
- E7b：之前仅 email/send-code、register、password/reset 转发云端，login/verify/activate 仍走本地桩；本轮补齐三者云端转发，客户端授权完全云端化。
- E8：前端密码最低长度统一为 8（注册/重置）；账号禁用消息经 login/verify 透传展示；`cloud_gateway` 显式设置 `User-Agent: FrameWeave-Client/0.2.10`，修正 OpenResty 对默认 `Python-urllib` UA 的 403 拦截。
- 客户端版本升至 0.2.11 并发布：GitHub Release v0.2.11（安装包 + blockmap + latest.yml）。
## 13. E9 密码哈希升级 与 E10 验证码持久化（2026-10-06）

- E9：新密码哈希改为 `scrypt$N$R$P$<hex>`（N=16384, R=8, P=1, dklen=32，Python 标准库 hashlib.scrypt，无第三方依赖）。旧 SHA256 哈希登录验证通过后自动升级为 scrypt（渐进迁移，无需用户改密）。独立实例验收：scrypt 注册/错误密码拒绝/正确登录/旧哈希登录后自动升级，全部 PASS。
- E10：验证码从内存字典迁到 SQLite。`email_codes` 表存未消费验证码（含 expires_at/attempts），新增 `send_log` 表记录每日发送历史（替代内存 _SENDS 的每日 10 次限制）。服务重启后未过期验证码仍有效。独立实例验收：发码→重启→重置成功，PASS。
- 生产已部署（0.2.11）：send_log 表已建，现存 test@fw.local 为旧哈希将在下次登录迁移。
