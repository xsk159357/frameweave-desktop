## 缓存修复（第三轮补丁，v0.2.4 已含）

### 问题
cache_index.json 只增不删：每次运行成功写入一条缓存，长期使用文件无限膨胀 + 启动加载变慢 + 内存增长；缓存引用已删除的资产时留下孤儿条目。

### 修复（engine.py）
- **上限淘汰**：缓存索引最多 2000 条，超出按最后使用时间(ts)淘汰最旧
- **孤儿清理**：条目引用的资产文件已不存在时删除（加载时 + 每次保存时）
- **LRU 刷新**：缓存命中刷新 ts，高频条目不会被误淘汰
- 落盘/加载均经过 trim，防回弹

### 验证
- 专项测试 6/6 PASS：孤儿清理 / 超限淘汰到 2000 / 淘汰最旧 / LRU 命中保留 / 新条目保留 / 加载仍受上限
- 功能回归 PASS：执行成功→资产落盘→二次执行缓存命中(CACHED)→参数变化重算(SUCCESS)→cache 文件 386B

## 安装器「无法关闭」修复（v0.2.4b）

### 现象
升级安装时始终提示「FrameWeave 无法关闭。请手动关闭它，然后单击重试以继续」，重试仍失败。

### 根因（electron-builder NSIS 模板）
_allowOnlyOneInstallerInstance.nsh 的 CHECK_APP_RUNNING：升级/卸载时检测到运行中的 FrameWeave.exe → taskkill（带 /fi "PID ne 自身"）→ 重试两次仍杀不掉 → 弹 appCannotBeClosed 并 Quit。旧版（0.2.3）主进程/白屏残留或权限场景下 taskkill 未生效 → 卡死。

### 修复（desktop/nsis-fixes.nsh）
利用模板预留的 customCheckAppRunning 钩子覆盖默认检测：安装/升级/卸载前无条件强杀
- taskkill /f /t FrameWeave.exe（含子进程树）
- taskkill /f /t frameweave-backend.exe（孤儿后端，锁 8788）
- Sleep 600 等文件句柄释放后再覆盖
无确认弹窗、不卡升级。已编译进 0.2.4b（二进制特征验证 ✓，sha512 校验 ✓）。

### 使用
关闭卡住的旧安装器 → 运行 release/frameweave/FrameWeave-Setup-0.2.4b.exe → 自动关闭旧版进程后安装。
