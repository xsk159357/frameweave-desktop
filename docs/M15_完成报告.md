### 3.2 安装环节问题排查（本轮用户关注点）

**现象**：安装器反复启动（--updated / 全新 /S /D 各种方式）但 apptest 版本始终 0.2.1，安装器进程 CPU 停滞、不写文件；带 UI 运行时弹出「FrameWeave 安装」向导并停在初始页。

**根因链**：

1. **electron-updater 的 installDirectory 恒为空**：查 electron-updater/out/nsisUpdater.js，installDirectory 仅在被读取的位置出现（if 判断后拼 /D= 参数），全文件无任何赋值点 → 升级安装器不传 /D，依赖 NSIS 自己定位。
2. **NSIS 定位到已存在的旧安装**：NSIS 从 HKCU\Software\<APP_GUID>\InstallLocation 读到 apptest 目录（v0.2.1 安装时写入）——但目标目录已存在旧版安装文件。
3. **已有安装 + 静默模式 = 卡住**：electron-builder 的 assisted NSIS 安装器检测到目标已有安装后走「旧版检测/覆盖确认」流程，/S 静默下既不弹确认也不执行安装（进程存活但 CPU 约 0.5s 后停滞）；交互模式下停留在安装向导首页等待点击（因此枚举窗口反复看到「FrameWeave 安装」）。

**解决**：卸载 v0.2.1（Uninstall FrameWeave.exe /S /currentuser，注册表键随之清除）→ 全新静默安装 0.2.2 到 apptest → 10 秒内完成，app.asar version = 0.2.2。

**结论**：NSIS 安装器对「目标目录已存在旧版本」的覆盖场景有静默限制，属官方安装器行为；真实产品语义下（用户从旧版启动 → 自动更新 → 安装器原地覆盖）因为 app 从默认 per-user 路径安装，NSIS 能正确定位并会走覆盖/卸载子流程，不受影响；本次卡顿源于测试目录被旧版残留占用。

## 四、升级后 WS 实机回归（M15③）

对升级后的 apptest(v0.2.2) 自拉起后端（8788 health 200）执行 WS 探针：

create wf: 201 → update nodes: 200 → WS connected → run: 200

- 第 1 次（真实执行）: node_update n1 pending → queued → running → success(1.0) → execution_done
- 第 2/3 次（缓存命中）: node_update n1 pending → cached(1.0) → execution_done
- RESULT: PASS；cleanup: 200

**execution_done 事件实机到达** —— M13 的 WS 修复（make_engine 由 async on_event 改为 ensure_future 投递）随 0.2.2 打包版确认生效（v0.2.1 的 backend-dist 不含该修复，事件不会到达）。

## 五、遗留发现与建议

1. **NSIS 自定义安装目录 + 已存在安装 + 静默覆盖会卡住**：自动化安装场景需先卸载旧版或清空目标目录；如产品支持自定义安装目录，发布说明中建议保持默认路径以便自动更新。
2. **electron-updater installDirectory 未赋值**（上游实现如此）：依赖 NSIS 注册表定位，标准路径安装无问题。
3. 点击器若干版本经验：SendMessage IDOK（WM_COMMAND）比 AppActivate+SendKeys 可靠；ps1 脚本必须 UTF-8 BOM（无 BOM 中文被 PS 5.1 按 GBK 读而错乱）。

## 六、结论

**M15 达成**：真实安装 → 启动 → 自动更新 0.2.1→0.2.2 全链路验证完成；升级后 0.2.2 实机 WS 事件链（pending→…→execution_done）通过。至此「安装 - 更新 - 运行 - 实时事件」发布闭环全部打通。

### 关键补充发现

1. **NSIS 的「已有安装」判断键** = HKCU\\Software\\<APP_GUID>\\InstallLocation（非 Uninstall 键）。此前所有安装卡住的根因是**该键残留指向 apptest**（v0.2.1 卸载未清 / 0.2.2 重装重新写入），导致后续任何安装（标准路径 / 更新）都误判「已有安装」并走覆盖确认流程、静默卡住。
2. **清理该键后**：标准路径安装立即成功（10s 内），自动更新原地升级也走通。→ 排查结论：遇到安装/更新卡住，先清 HKCU\\Software\\<APP_GUID> 残留。
3. **升级安装器（--updated）以 isSilent: false 运行**（main.cjs quitAndInstall 默认值）→ 交互式向导需用户点击；自动化验证用 WM_COMMAND IDOK 推进（默认按钮：下一步→安装→完成）。
4. **app 已下载 + 触发过安装器后**，每次启动会再次触发 quitAndInstall（日志 repeated Executing → Quitting），属 electron-updater 正常状态机。
