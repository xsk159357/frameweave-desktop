# v0.3.7 t3：修复「创建工作流后无法添加节点」记录

> 来源任务：fw-next-version-fixes 团队 t3（工作流与节点交互工程师 workflow-flow，attempt 78816b3f-2996-4910-b2af-cc35a1082664）。
> 验收要求：新建工作流可立即添加节点；切换工作流后画布与节点库可用；空节点库仍给出正确引导；`npm run build`、`npx tsc --noEmit` 通过。

## 1. 问题现象

新建（或启动后自动创建）一个工作流后，向空画布添加节点（空画布「添加第一个节点」按钮 / 画布空白右键菜单 / 节点库点击或拖拽）时，节点出现后很快被清空，用户感知为「无法添加节点」。切换工作流后同样存在未保存编辑被还原的连带症状（拖拽回弹同类根因，见 t2）。

## 2. 根因分析（前端时序竞态，非后端问题）

### 2.1 `fw-nodes-installed` 自续广播环（循环刷新）

- `store.ts` `setSpecs`：无条件 `set({specs})` + 无条件 `dispatchEvent('fw-nodes-installed')`。
- `Canvas.tsx` 监听该事件：`nodeSpecs().then(setSpecs)`（安装后自动刷新 specs 用）。
- 两者形成 **set → 广播 → 拉取 → set → 广播 → …** 的无限异步自续环（本地引擎响应毫秒级，循环以网络延迟为周期永续）。
- 由于 `objectInfoToSpecs()` 每次调用都构建**新的数组引用**，每轮循环 `specs` 身份都变化。

### 2.2 工作流加载效果把 specs 当依赖 → 每轮循环整流重拉 → 覆盖画布

- `Canvas.tsx` 工作流加载效果依赖 `[workflowId, specs]`：每轮 specs 身份变化都重新执行 `api.getWorkflow(workflowId)`，并把返回值 `setNodes(nds)` **整体替换**画布节点。
- 新建工作流后：用户在两次循环之间添加节点 → 下一轮 getWorkflow 返回服务端空节点 → `setNodes([])` 把刚添加的节点清掉。窗口只有几十毫秒，人眼看到的就是「节点加不进去」。
- 附带影响：未保存的参数修改、节点拖动位置、未保存连线在循环中被服务端状态还原（与 t2「画布节点拖动」同一根因）。

### 2.3 次要竞态

即便循环终止，新建工作流后 `setWorkflow(id)` → 清空 → `getWorkflow` 异步返回期间，用户若极快添加了节点，返回的空节点列表仍会覆盖本地新增。

## 3. 修复内容

### 3.1 `web/src/store.ts` — setSpecs 变化签名去重（终止自续环）

- 新增模块级 `specsSignature(specs)`：`type_id@version` 排序连接串（顺序无关、幂等）。
- `setSpecs`：仅当签名与当前 store 中 specs 不同才 `set` + 广播 `fw-nodes-installed`。
- 效果：真实安装/升级/卸载 → 广播一次 → 监听方拉取到同内容 → 去重忽略，循环终止；顺序无关保证 `/api/object_info` 键序抖动不会误判变化。
- 保留原有「节点库变化后广播」契约（画布/右键菜单/节点库/插件 web 扩展联动刷新）。

### 3.2 `web/src/Canvas.tsx` — 工作流加载与 specs 解耦 + 就地补规格 + 竞态防护

1. **加载效果依赖改为 `[workflowId]`**：specs 变化不再触发整流重拉/整体覆盖画布（消灭 2.2 的覆盖循环）。
2. **新增 specPatch 效果（依赖 `[specs, setNodes]`）**：specs 就绪/更新后，在现有节点上**就地**补齐 `spec/title/category` 并清除「未安装」标记，不重拉工作流、不覆盖任何本地编辑——保留 commit `17e2bd2`「等待节点规格加载后重绘」语义。
3. **初始化竞态防护 `editSeqRef`**：`createNode` / `createAndConnect` / `paste` / `importWorkflow` 每次本地建节点时递增；加载效果在 `getWorkflow` 返回前记录 `seqAtStart`，返回时若序号已变（加载窗口内用户已添加节点）则**跳过服务端覆盖**，本地优先。

### 3.3 未改动部分（验收点依赖的既有行为）

- 空节点库引导（`specs.length === 0` →「去商城安装节点 / 导入节点插件 / 刷新节点」覆盖层）与空画布引导（`nodes.length === 0 && specs.length > 0` →「添加第一个节点」）渲染条件原样保留。
- 节点库抽屉（点击 `__fwAddNode` / 拖拽 `application/fw-node`）与画布右键 addMenu 事件链路未动，修复后随 specs 稳定自然可用。

### 4.4 流程行为推演（对照验收要求）

1. **新建工作流可立即添加节点**：`createWorkflow`（后端立即持久化，GET 返回空节点）→ `setWorkflow(id)` → 加载效果清空并拉取一次；specs 不再变化（循环已终止）→ 空画布出现引导 → 点击/右键/节点库添加 → `createNode` 建节点 → 无后续整拉覆盖，节点保留；加载窗口内的添加由 `editSeqRef` 守卫保护。
2. **切换工作流后画布与节点库可用**：`open(id)` → `setWorkflow(id)` → 清空 + 单次拉取该工作流 → 节点/连线按保存态渲染；节点库与右键菜单按当前 specs 渲染（specs 只随真实安装变化，安装后经 specPatch 就地生效）。
3. **空节点库仍给出正确引导**：specs 为空时「FrameWeave 节点库为空 → 去商城安装节点」覆盖层照常显示；空列表签名幂等不会引发广播环。
