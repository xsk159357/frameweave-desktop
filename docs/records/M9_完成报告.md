## 2. M9① 后端参数快照

### 实现（engine.py）
- GraphNode 新增 `last_params` 字段（默认 {}）
- **SUCCESS 时**：`node.last_params = dict(node.params)` 记录本次运行参数
- **缓存命中时**：同样记录快照（缓存复用也算「上次运行」）
- to_dict / from_dict 双向序列化；server.py PUT 保存时继承旧快照（不丢失）

### 语义说明
- 只有成功/缓存命中的节点有快照；pending/failed 无快照（无「上次运行」可对比）
- 旧工作流 JSON 无快照字段 → 加载后为空，重跑一次才有对比基准

## 3. M9② 前端差异高亮

### 实现（FlowNode.tsx + Canvas.tsx + types.ts）
- Canvas 加载工作流时把 `last_params` 与真实运行状态（status/error/progress/asset_ids）带入节点 data
  （顺带修复：刷新后节点不再全部显示 pending）
- FlowNode 计算差异：`JSON.stringify` 逐键对比当前 params 与 last_params
- 有差异时：
  - 标题旁「参数改动」黄色徽标（hover 显示改动字段）
  - 节点内橙色提示行 `⚑ 已改: 字段1, 字段2`

### 业务闭环
参数改动 → 节点黄色高亮 → 右键「重置状态/运行下游」强制重算 → 高亮消失

## 5. 已知边界
- 字符串化对比用 JSON.stringify，参数值类型变化（如 "2" vs 2）会误报差异——可接受
- 快照只在 SUCCESS/CACHED 记录，接口行为变更后旧快照无法自动失效（需手动重置）
- 数组/嵌套对象参数同样按 JSON 对比，正常支持
