# 0.3.3 开发记录：商城下载修复 + 工作流模板上架（2026-10-14）

## 1. 商城无法下载节点 — 根因与修复

### 根因
客户端前端 `MarketPage.tsx` 经 `download-auth` 拿到韩国服务器直链后，用浏览器/Electron `fetch(url)` **跨域**下载 `https://shouquan.frameweave.top/plugins/*.zip`。韩国服务器 OpenResty 站点 conf 未配置 `Access-Control-Allow-Origin`，浏览器/Electron 渲染进程按 CORS 拦截 →「商城无法下载节点」。

（2026-10-13 迁移到韩国前，插件走 GitHub Release 直链，天然带 `ACAO: *`，故旧版正常；迁移后服务器未同步 CORS 头导致回归。）

### 修复（韩国服务器 `shouquan.frameweave.top` 站点 conf）
- 文件：`/opt/1panel/www/conf.d/shouquan.frameweave.top.conf`（容器内 `/www/conf.d/...`）
- 变更：`/plugins/` 与 `/update/` 两个 location 增加
  `add_header Access-Control-Allow-Origin * always;`
  `add_header Access-Control-Allow-Methods "GET, HEAD, OPTIONS" always;`
  `add_header Access-Control-Allow-Headers "Content-Type, X-FW-Local-Token" always;`
  （保留 `Strict-Transport-Security`；`nginx -t` 通过 + reload 生效）
- 备份：`shouquan.frameweave.top.conf.bak_cors_*`（2 份）
- 验证：`/plugins/core_tts.zip`、`/update/latest.yml`、`/update/FrameWeave-Setup-0.3.2.exe` 均 `HTTP 200 + ACAO=* + STS` ✅

## 3. 客户端行为

- 商城已按 kind 分区显示：节点使用「下载并安装」，工作流使用「下载并导入」；卡片图标/操作文案明确区分。
- 工作流下载后调用本地 `POST /api/workflows/import`，校验 zip 内 `workflow.json`，写入模板注册表；成功后可从左侧「从模板新建」立即创建工作流。
- 用户可在左侧工作流栏点击「导入分享」，导入其他用户分享的工作流 zip；导入后进入本地模板列表，可创建为新的工作流。
- 用户原有工作流继续支持「导出工作流 zip」，分享包可跨用户导入；服务端导入采用模板校验与安全 zip 解包，不直接覆盖 workflows 数据。
- `min_client_version=0.3.3`：旧客户端不具备工作流导入 API，云端工作流条目会拒绝旧版本下载，避免误走节点安装链路。

## 4. 遗留与建议

- 工作流模板为 v1（官方免费）；后续可按需扩展更多模板（配音/混剪/翻译已覆盖三类典型场景）
- 模板 zip 未签 ed25519 签名（`sig_sha256` 字段留空）——kind=workflow 安装链路 `install_workflow_zip` 不强制验签；如需签名防护可接入 `frameweave-plugins/sdk/sign_core_manifests.py` 体系
- 韩国服务器 conf 已有 CORS 备份文件，后续修改注意保留
