## 2. 前后台 API 对齐核对

- admin.html `call('/xxx')` → `POST /api/admin/xxx`，全部 23 个调用路径均在 `cloud_server.ROUTES` 注册：`login / stats / users / user/get / user/extend / user/credits / user/toggle / user/kick / audit / issue-card / cards / card/revoke / market/list / market/upsert / market/stats / settings / settings/get / key/rotate / tokens / token/revoke / backup / restore / ops`。
- 未在 UI 调用的已注册路由（`devices / device/reset / logout / auth/* / market/download-auth / market/install-report`）属客户端/API 层契约（auth 与 market 路径由客户端与网关使用，devices 列表经 `/user/get` 展示），非缺口。
- 商城条目编辑器（status/official/size/min_client_version 等）与上下架切换均走 `/market/upsert`；危险操作全部经确认弹层后调用，无假按钮（t2 已逐项对照）。

## 3. protocol / auth / market 健康字段

`/api/health` 契约在 t1/t3 改动后保持不变：`protocol_version=3`、`auth_revision=email-code-v2`、`market=v1`；`/api/auth/verify` 签名与 nonce 回显契约未变（签名长度 48 实测）。客户端旧版本兼容无需变更。

## 6. 回滚步骤（若上线后出现契约/可用性问题）

前置事实：
- `update-cloud-auth.ps1` 上传前自动在服务器生成 `backups/<时间戳>/cloud_server.py`（旧版本源文件副本）。
- 备份/恢复 API 会生成 `backups/pre_restore_*.db` 快照（保留最近 10 份），恢复事务化。

### 6.1 代码回滚（首选，分钟级）
1. SSH 登录服务器：`ls -t /opt/frameweave-cloud/backups/ | head`，取最近一份含旧 `cloud_server.py` 的备份目录。
2. `cp -a /opt/frameweave-cloud/backups/<ts>/cloud_server.py /opt/frameweave-cloud/cloud_server.py`。
3. `python3 -m py_compile /opt/frameweave-cloud/cloud_server.py && systemctl restart frameweave-cloud`。
4. `curl -s http://127.0.0.1:8789/api/health` 确认恢复（旧版本号）。
5. 若上一版本无 `admin.html` 或 UI 有回归：`update-cloud-auth.ps1` 不支持单独回滚 admin.html 时，手工将旧 `admin.html` 一并从备份恢复（如存在）。

### 6.2 数据回滚（仅当恢复/设置/用户数据被误操作，谨慎）
1. 定位服务器 `backups/pre_restore_*.db` 或管理员手工下载的备份 JSON。
2. 经管理后台「备份恢复」或直接恢复 DB 文件（先再备份当前 DB）。
3. 恢复后所有会话 token 已重置 → 客户端用户需重新登录（正常现象）。

### 6.3 决策红线
- 任一上线后检查项不满足（health 契约/空密钥被拒/响应头缺失/客户端兼容失败）→ 执行 6.1 代码回滚，并记录失败现象到 `docs/records/`。
- 出现积分/卡密/数据异常 → 先冻结管理后台写操作，评估是否 6.2；未经用户确认不得覆盖生产数据。
- 回滚后复跑 §5.1 本地验收确认差异点。

## 7. 遗留与风险（转队长/用户）

1. `.tmp/` 约 70 个脚本含明文 root 口令：需用户处置（轮换 + SSH 密钥迁移 + 隔离），处置前发布脚本不得启用 `-AllowLegacyFallback`。
2. backend 现存 `fw_*` 测试 scratch 目录（pytest 运行产生）：属工作区卫生项，健康度 canary 测试将持续失败直至登记/归档（**不影响本发布，非代码缺陷**）。
3. `FRAMEWEAVE_VERIFY_SECRET` 默认值内嵌客户端：纵深防御层，服务端判定为准（t3 已记录）。
4. 商城积分竞态已由 t1 修复（原子 UPDATE + `_clean_key`），建议上线后观察一周积分/下载对账。
