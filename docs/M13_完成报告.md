## 2. 抓到并修复的 3 个真实 Bug

### 🔴 Bug 1（核心）：WebSocket 事件全部丢失 → UI 永远卡「执行中」
- **症状**：API 层节点全部 success，但页面运行按钮一直「⏳ 执行中」，进度条不动
- **根因**：server.py 的 `make_engine()` 里 `ev` 是 `async def`，但 engine.`_emit()` 同步调用 `self.on_event(ev)` **不 await** → coroutine 从未被调度 → **所有 WS 事件（node_update/execution_done/进度）静默丢失**
- **为什么现在才发现**：这个 Bug 从 M0 就存在，之前里程碑验证走 API 层（轮询 GET 节点状态）没暴露；UI 实时性从未真正工作过
- **修复**：`make_engine()` 改为同步包装 + `asyncio.ensure_future(_broadcast(evt))` 投递回事件循环
- **验证**：WS probe 收到完整序列 `pending→queued→running→success 1.0→execution_done`（修复前 20s 零事件）

### 🟠 Bug 2（M11 遗留）：ParamPanel run_history 未解构 → 双击节点 React 崩溃
- **症状**：双击任意节点 → `ReferenceError: run_history is not defined` ×3 → 参数面板渲染失败
- **根因**：M11 改 ParamPanel 时 Props 替换只改了内存未写盘，历史区块代码引用了未解构的 run_history
- **修复**：Props interface + 函数签名补 run_history 解构
- **验证**：双击节点 → 运行历史区块正常显示

### 🟠 Bug 3（M5 遗留）：Canvas `apiResetNode` 未定义 → 右键「重置状态」点击崩溃
- **症状**：右键菜单选「↺ 重置状态」→ `ReferenceError: apiResetNode is not defined` → React 整棵树崩溃
- **根因**：Canvas 引用不存在函数（重置功能从未接线）
- **修复**：定义 `resetNode`（调 api.resetNode force）+ 修正引用
- **验证**：tsc 无该错误，dist 确认无 apiResetNode
