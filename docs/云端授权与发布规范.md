# FrameWeave 云端授权与发布规范

> 文档用途：统一记录授权服务器、客户端认证、密钥边界、打包发布和验收规则。
> 版本基线：v0.2.10
> 更新时间：2026-10-05

## 1. 服务器定位

“雨云日本中转”服务器用于 FrameWeave 云端授权，不用于文档存储。服务器职责：账号、QQ 邮箱验证码、登录、密码重置、设备绑定、订阅校验、卡密激活与管理签发。

服务器地址、root 密码、AccessKey Secret 和其他凭据严禁写入本文件、源码、日志、安装包、GitHub 或聊天记录。曾经暴露的凭据必须轮换。

## 2. 目标架构

客户端通过 HTTPS 访问 `frameweave.ameaaos.com`，Nginx 反代至 `127.0.0.1:8789` 云端授权服务。DirectMail 凭据只存在服务器。正式客户端不携带阿里云 AccessKey，不在客户端签发或验证卡密，不以本地文件作为正式账号数据源。

## 3. 云端认证接口

- `POST /api/auth/email/send-code`
- `POST /api/auth/register`
- `POST /api/auth/login`
- `POST /api/auth/password/reset`
- `POST /api/auth/verify`
- `POST /api/auth/activate`
- `GET /api/health`

注册需要 QQ 邮箱验证码、密码和确认密码；注册不需要卡密。卡密在登录后的账户能力中独立激活。

## 4. DirectMail 密钥边界

AccessKey、发信地址和服务配置只放在服务器环境变量或服务器端 `.env`，不进入前端、Electron、安装包、GitHub Release、Git 历史、日志和错误回显。项目根 `.gitignore` 必须忽略 `.env`、`*.env` 和 `backend/.env`。

## 5. 验证码规则

- 仅接受规范化后的 `@qq.com` 地址
- 验证码 6 位数字，5 分钟有效
- 成功验证立即失效，错误 5 次后失效
- 同邮箱 60 秒冷却，每日最多 10 次
- 发送和校验必须有并发保护
- 找回密码不得直接暴露账号是否存在
- 正式部署应增加 IP、设备和全局限流，并记录发送审计

## 6. 客户端与本地后端边界

客户端本地后端负责工作流、媒体处理、节点运行和本地素材。正式账号、订阅和卡密状态以云端为准。协议握手字段为：`service=frameweave`、`version=0.2.10`、`protocol_version=3`、`auth_revision=email-code-v2`。Electron 只有在字段兼容时才复用 8788 端口；启动前清理旧后端进程树。

## 7. 打包强制流程

`build-installer.ps1` 必须先调用 `build-backend.ps1`，禁止复用旧 backend-dist。顺序：PyInstaller 重建后端、校验 EXE、校验认证路由、构建前端、构建 Electron、生成 NSIS、生成 latest.yml/blockmap、VM 验收、上传 GitHub Release。

## 8. 发布规则

认证/API/协议改动必须升级版本号。0.2.10 是当前全量加固版本。GitHub Release 必须包含安装包、blockmap、latest.yml，并验证下载 URL、大小、SHA512 和 VM 安装结果。首次分发和 OV 代码签名按既定决策暂不处理。

## 9. 当前验收基线

已验证：阿里云 DirectMail 真实发送、后端语法、TypeScript、Vite、PyInstaller、NSIS、OpenAPI 认证路由、健康接口、build-info 和 v0.2.10 GitHub 发布。

长期升级：部署云端授权、迁移云端数据库、Argon2id/scrypt 密码迁移、Redis/数据库验证码存储、HTTPS/Nginx/systemd 正式部署。
